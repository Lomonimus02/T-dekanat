# Безопасность

| Угроза | Мера |
|---|---|
| Чтение чужих данных (IDOR) | Владение проверяется в каждом SQL-запросе (`WHERE student_id = $ctx`). Чужая заявка, документ, дисциплина, сеанс → **404**; чужой id студента в пути → **403**. Тест: `tests/security.test.mjs` (API и URL в браузере). |
| Эскалация роли | `requireRole('student')` / `requireRole('staff')` на роутерах; студент на `/api/staff/*` → 403, сотрудник на студенческом API → 403. |
| Пароли | bcrypt (cost 11). Время ответа выравнивается фиктивным хешем, если логин не найден. Ответ «неверный логин или пароль» без уточнения. |
| Перебор паролей | 8 неудач на логин или 20 на IP за 15 минут → 429. |
| Сессии | Случайный 256-битный токен в cookie `sd_sid` (HttpOnly, SameSite=Lax, Secure, Path=/dekanat). В БД хранится только HMAC-SHA256 токена. Срок 7 дней, просроченные удаляются ежечасно. Список сеансов с возможностью завершить; выход удаляет сессию. |
| CSRF | Изменяющие запросы требуют заголовок `X-Requested-With: stellar` и совпадающий `Origin`; плюс SameSite=Lax. |
| XSS | React экранирует вывод; CSP `default-src 'self'`, `script-src 'self'`, без inline-скриптов; `frame-ancestors 'none'`. |
| Персональные данные | Номер зачётки, e-mail, телефон, дата рождения зашифрованы AES-256-GCM (`DATA_KEY`), в интерфейсе скрыты маской до нажатия. |
| Спам заявками | Не больше 15 новых заявок в час на студента (429). |
| Валидация | zod-схемы на всех входах; поля заявок — только из справочника; переходы статусов — только допустимые. |
| Секреты | Только в `/opt/stellar-dekanat/.env` (chmod 600) и локальном `.env`; оба в `.gitignore`. В браузер секреты не попадают (проверяется тестом). |
| Кэширование | `Cache-Control: no-store` для API. |
| Подделка справок | Электронная справка получает случайный код; публичная страница `/verify/:code` показывает только номер, тип, дату и фамилию с инициалами. |
| Аудит | Вход, выход, создание заявок, просмотр и смена статусов сотрудником, а также попытки открыть чужие данные пишутся в `audit_log`. |
