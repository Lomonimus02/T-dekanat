# Правила для ИИ-агентов

Проект — конкурсный прототип кабинета студента «Stellar · Деканат». Перед изменениями прочитайте
`docs/architecture.md` и `docs/security.md`.

## Жёсткие правила

1. **Секреты только в `.env`** на сервере (chmod 600). Никогда не пишите пароли, ключи, строки подключения
   и пароль root в код, коммиты, документацию, логи или ответы пользователю. `.env*` в `.gitignore`,
   кроме `.env.example` с пустыми значениями.
2. **Владение данными проверяется в SQL**, а не на клиенте: каждый студенческий запрос фильтрует по
   `student_id` из сессии (`ctx.studentId`). Чужой объект — `404`, явный чужой id в пути — `403`.
   Новый эндпоинт без такого условия — ошибка. Добавили маршрут — добавьте проверку в `tests/security.test.mjs`.
3. **Роли разделены**: `/api/staff/*` — только `staff`, остальное `/api/*` — только `student`.
4. Все изменяющие запросы требуют заголовок `X-Requested-With: stellar` и совпадающий `Origin` (CSRF).
   Клиентский `api()` делает это сам — не обходите его.
5. Входные данные валидируются zod-схемами; поля заявок — только из `shared/requests.ts`.
6. **Только вымышленные данные.** Никаких реальных людей, вузов, логотипов.
7. **Сервер общий.** На нём работают другие сайты (stellarschool.ru, altair, dejaview и др.).
   Не трогайте их файлы, процессы pm2, базы и блоки Caddy. Перед изменением конфигурации — резервная копия,
   `caddy validate`, затем `systemctl reload caddy` (не restart). Код основного сайта Stellar
   (`/var/www/stellar`) не меняйте: его перезаписывает деплой из GitHub.
8. Сервер слабый (1 CPU, ~1 ГБ RAM): собирайте на своей машине, на сервер копируйте `dist/`.

## Дизайн

- Все цвета, радиусы и тени — токены из `client/src/styles/app.css` (`--brand`, `--red`, `--ok`, `--warn`, `--blue`,
  `--r*`, `--sh-*`). Новых «случайных» цветов не вводить.
- Фирменный жёлтый `--brand` — только с чёрным текстом (`--ink`). Белый текст на жёлтом запрещён (контраст < 1.3:1).
- Карточки — белые, скругление 16–24px, мягкая тень; кнопки 12–14px; чипы и фильтры — «таблетки».
- Мобильная версия обязана работать с 360px. Сетки — `minmax(0, 1fr)`, длинные строки — `ellipsis` или перенос.
  Горизонтальные ленты (истории, фильтры) — класс `.hscroll`.
- Анимации 200–300 мс (`--t`), без отскоков, уважают `prefers-reduced-motion`.
- После любой визуальной правки — `tests/screenshots.mjs` по всем ширинам и ролям; `_problems.json` должен быть пустым,
  и скриншоты нужно посмотреть глазами.

## Названия и расположение

- Разделы и блоки называются простыми словами, как в обычном кабинете вуза: «Главная», «Расписание», «Успеваемость»,
  «Заявки и справки», «Уведомления», «Профиль», «Поиск», «Ближайшие дедлайны», «Изменения в расписании», «Мои заявки».
  Никаких придуманных брендов для разделов («Пульт», «Штурман» и т. п.).
- Анатомия каждой страницы: заголовок `h1` + `.page-sub` → главное действие справа (на телефоне — `.fab` или
  кнопка в конце формы) → вкладки `.seg.page-tabs` или `.filter-chips` → карточки `Panel` → понятное пустое состояние.
- Главная — истории, «Требует внимания» (≤ 3 пункта) и плитки-сводки со ссылками в разделы. Длинные списки на главную
  не добавлять.
- Компактность: страница на телефоне — 1–2 экрана. Не делить информацию на много подблоков: одна карточка-список
  (`.list-card`), второстепенное — в `<details class="acc">`. Изменения расписания показываются в карточке занятия.
- Телефон: нижняя панель не больше 5 пунктов (последний — «Ещё»); вложенные страницы получают кнопку «назад» в шапке
  через `backTarget()` в `Shell.tsx`; ссылки «назад» в контенте — класс `.back-link` (на телефоне скрыты);
  зоны нажатия ≥ 44 px — это проверяет `tests/screenshots.mjs`.

## Деплой

```bash
npm run build
tar czf /tmp/dk.tgz dist ecosystem.config.cjs package.json
scp /tmp/dk.tgz srv:/tmp/ && ssh srv 'cd /opt/stellar-dekanat && rm -rf dist && tar xzf /tmp/dk.tgz && pm2 reload stellar-dekanat'
```
Миграции применяются при старте. `seed` **стирает** данные кабинета — запускать только осознанно.
